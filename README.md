# Discord-бот Stage Role Play | 01

## Запуск
```
pip install -r requirements.txt
python bot.py              # запуск бота
python bot.py --selftest   # проверка связи с сервером (без запуска бота)
```
Настройки — в файле `.env`.

## Команды
| Команда | Кто может | Что делает |
|---|---|---|
| `/status` | все | онлайн/офлайн, игроки, пинг, адрес |
| `/online` | все | список игроков онлайн |
| `/srv <команда>` | админы бота | админ-команда на игровой сервер (`help` — список) |
| `/say <текст>` | админы бота | сообщение всем игрокам |
| `/admins` | админы бота | игровые админы онлайн и в базе |
| `/setadmin <ник> <1-6>` | **только владелец** | назначить игрового администратора |
| `/removeadmin <ник>` | **только владелец** | снять игрового администратора |
| `/setlogchannel <категория> <канал>` | **только владелец** | куда слать логи этой категории (`all` — все остальные) |
| `/clearlogchannel <категория>` | **только владелец** | убрать канал категории |
| `/logchannels` | **только владелец** | текущая раскладка каналов |
| `/adminlog <ник> [дней]` | админы бота | журнал действий админа (категории `admin`, `adminchat`), последние ~25 |
| `/searchlog <ник> [категория] [дней]` | админы бота | поиск в логах по нику |
| `/stats [дней]` | админы бота | онлайн по дням (среднее/пик), деньги в обороте, топ жалоб, активность админов |
| `/player <ник> [дней]` | админы бота | карточка игрока по логам: последний вход, записи по категориям, последние события |

## Команды в личных сообщениях боту
Напишите боту в личку команду **как в игре, со слешем**:
- админы бота (`OWNER_DISCORD_ID`, `ADMIN_DISCORD_IDS`): любые команды `/srv` — `/ban 5 3 причина`, `/kick 5 причина`,
  `/givemoney 5 1000`, `/msg текст`, `/settime 12`, `/admins`, `/say текст`... `/srvhelp` — полный список с сервера;
- все: `/status`, `/online`, `/link 123456`, `/myaccounts`, `/help`.
Ответ сервера приходит в ту же личку. Сервер ещё раз проверяет Discord ID и уровень команды (`stage_discord.cfg`).
Включать Message Content Intent не нужно: текст личных сообщений бот получает и без него. Одна команда в 1,5 с.

Бот сам показывает в Discord статус сервера (`Онлайн: N/M` или `Сервер выключен`). Если указать `STATUS_CHANNEL_ID`, он ведёт в канале одно обновляемое сообщение со статусом.

## Настройка (.env)
- `OWNER_DISCORD_ID` — Discord ID владельца. Только он может назначать/снимать админов.
- `ADMIN_DISCORD_IDS` — остальные, кому разрешены `/srv`, `/say`, `/admins` (через запятую).
- `SAMP_HOST`, `SAMP_PORT` — адрес игрового сервера. Если сервер отвечает на другом порту, бот найдёт его сам по списку `SAMP_FALLBACK_PORTS` и напишет в лог, что указать.
- `SAMP_RCON_PASSWORD` — тот же, что `rcon_password` в `server.cfg`. Задайте длинный случайный пароль.

На игровом сервере те же ID должны быть в `scriptfiles/stage_discord.cfg`:
```
owner=<ID владельца>
admin=<ID админа бота>
```
Права проверяются дважды: в боте и на сервере. Через Discord можно выдать уровни 1–6; администраторов 7 и 8 уровня бот менять не может.

## Если бот пишет «сервер недоступен», а сервер включён
1. `python bot.py --selftest` — покажет, какой порт отвечает.
2. В `server.cfg` должно быть `query 1`.
3. Должен быть открыт UDP-порт сервера (а не только TCP).
4. `SAMP_HOST` должен быть адресом, доступным с компьютера, где запущен бот.

## Логи сервера в Discord
Сервер (`API/discord_logs.inc`) раз в 4 секунды одним HTTP POST отправляет боту накопленные логи. Бот сохраняет их в `botdata.sqlite` (хранятся 30 дней), а затем раз в ~5 секунд рассылает в каналы, которые выбрал **владелец**.

1. В `.env` бота: `LOG_SECRET` (длинная случайная строка, не короче 12 символов), `LOG_HTTP_HOST`, `LOG_HTTP_PORT` (по умолчанию 8099). Пример — `.env.example`.
2. В `scriptfiles/stage_discord.cfg` на игровом сервере: `log_url=host:port/path` (например `127.0.0.1:8099/log`, без `http://`) и `log_secret=` — **тот же** секрет, что `LOG_SECRET`. Без этих строк отправка выключена.
3. Если бот на другой машине — откройте TCP-порт `LOG_HTTP_PORT` и укажите в `log_url` адрес этой машины.
4. В Discord владелец вызывает `/setlogchannel`: категория → канал. Бот проверяет, что может писать в канал. Если канал для категории не задан, используется `all`; если и его нет — записи только сохраняются (для `/adminlog`, `/searchlog`, `/stats`).

Категории: `admin`, `adminchat`, `adminreport`, `join`, `money` (суммы от 100 000), `donate`, `vehicle`, `inventory`, `server`, `casino`, `report`, `ask`, `events`, `alert` (разовые суммы от 5 000 000 и скачок экономики >20% за час), `sqlerror` (ошибки SQL сервера). Категория `stats` (онлайн раз в 5 минут и экономика раз в час) в каналы не рассылается — только для `/stats`.

Проверка: `python bot.py --selftest` (в конце проверяет приём POST в том же формате, что шлёт Pawn). Приём защищён секретом (сравнение через `hmac.compare_digest`), лимит тела 64 КБ, 10 неверных попыток с одного IP в минуту — временная блокировка.

Недельный отчёт: по понедельникам в 10:00 (время машины бота) сводка `/stats` за 7 дней уходит в канал категории `server` (если не задан — в `all`).

## Страница статистики (сайт)
Тот же HTTP-сервер бота отдаёт страницу `http://адрес:LOG_HTTP_PORT/stats` (онлайн по дням и за сутки, деньги в обороте, топ жалоб, активность админов) и JSON `/stats.json`. Параметр `?days=1..30`.
Доступ защищён ключом `STATS_PAGE_KEY` из `.env`: `http://адрес:8099/stats?key=<ключ>`. Если ключ пустой, страница открыта всем (на ней только агрегированные данные). Для публичного сайта поставьте перед ботом nginx/Cloudflare с HTTPS.
